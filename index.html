Práctica 1: Sistemas de control de versiones

Repositorio: curs-javascript-gitflow

Introducción: Git y Git Flow

Git es un sistema distribuido de control de versiones. Guarda el historial del proyecto y permite comparar cambios, recuperar versiones y trabajar en ramas.

Git Flow organiza el trabajo mediante ramas: main contiene versiones estables; develop integra el desarrollo; feature/ sirve para nuevas funciones; release/ prepara una versión; y hotfix/ corrige problemas urgentes de producción.

Usamos este modelo para separar el trabajo de cada sección, integrar los cambios de forma controlada y etiquetar las versiones publicadas.

Proceso realizado

1. Estructura inicial y features

Se preparó el repositorio y las ramas principales. En develop se integraron las features feature/contingutHTML, feature/atributsHTML y feature/estilsCSS, además de la estructura inicial de la página.

2. Release v1.0

Se creó release/v1.0 desde develop, se añadió la nota de versión al README y se integró la release en main y develop. Se creó la etiqueta v1.0.

3. Hotfix

La rama hotfix/milloresV_1_0 contiene una mejora de la sección de contenido. Se integró en main y develop y se etiquetó como v1.0.1.
